# Halal certifiers directory (for exporters)

A B2B corner of halalfood.world: which foreign halal certification bodies each importing country's halal authority
accepts, copied from the official lists, with scopes, dates and the date we last checked. Milestones M0–M2 are built:
schema and BPJPH seed, the source check, and the public pages and API. Alerts are stored but not sent (double
opt-in is M4). JAKIM, MOIAT and GAC come later; no rows for them exist yet.

## Rules

1. **Status only comes from the official source**, shown with the source link and the last-checked date. Certifiers'
   own sites, consultants and news are never evidence; at most they tell us where to look.
2. **Copy, never invent.** Name (trimmed), where the body is based, address, scopes in the source's words
   (`scopes_raw`), valid-until, registration number and the source's own status word (`source_status`, BPJPH: `MRA`).
   A missing date shows "No date on official list"; a missing number shows "Not given". No websites or emails unless
   an official source gives them.
3. **Expired is computed at render time** from `valid_until` against today (UTC), and shown as expired on the
   official list's own date. It is never stored.
4. **Traceable.** Every check stores the raw pages in R2 (`certifier-sources/<authority>/<date>/page-N.html`) and a
   `cert_snapshot` row; every change records the snapshot it came from.
5. Change kinds and statuses are stable strings: add, never repurpose (`added`, `removed`, `scope_added`,
   `scope_removed`, `date_changed`, `renamed`, `expired`, `status_changed`; `recognised`, `expired`, `suspended`,
   `removed`, `pending`).

## Data

Tables (migration `0004_certifiers.sql`): `cert_authority`, `certifier`, `certifier_alias`, `certifier_slug_history`,
`recognition` (one row per certifier × authority), `scope`, `scope_map`, `cert_source`, `cert_snapshot`,
`cert_change`, `cert_alert_sub`. `0005_certifiers_seed_bpjph.sql` seeds BPJPH, its source, the scope vocabulary and
mapping, and the 124 bodies on BPJPH's list as read on 17 Oct 2026 (`seed/certifiers/bpjph-lhln-2026-10-17.json`). It
is generated by `scripts/certifiers-seed-sql.ts`; `lib/certifiers/seed-sql.test.ts` fails if the two drift.

Country names are mapped to ISO codes in `lib/certifiers/countries.ts` (BPJPH writes "Polandia", "Kolombia"), and
scope wording to our codes in `lib/certifiers/scopes.ts`. An unmapped country stays null; an unmapped scope stays in
`scopes_raw` and is reported by the check.

## The source check (`lib/certifiers/check.ts`)

1. Fetch every page of each active source (`?page=N`), user agent
   `halalfood.world certifier check (+https://halalfood.world/certifiers/methodology)`, 1 s between pages, up to 3
   tries on network errors, 429 and 5xx.
2. Store each page in R2, then parse (`lib/certifiers/bpjph.ts`: the rows are Next.js flight data in
   `self.__next_f.push` chunks, after `"data":[{"lph_id"`). Any page that fails to parse, duplicate rows, or a row
   count that differs from the page's own `totalItems` fails the run: a failed snapshot, `needs_look = 1`, no diff.
3. Hash the parsed rows in a stable form. Same hash as the last good snapshot: record the snapshot, update
   `last_checked_at` / `last_seen_at`, stop.
4. Match rows to recognitions by the source's own id (`source_key`, BPJPH `lph_id`), then by normalised name
   (`lib/certifiers/names.ts`: case, accents, punctuation, bracketed abbreviations, trailing legal forms).
5. Diff (`lib/certifiers/diff.ts`). **Safety rule:** if the list has more than 10% fewer rows than the bodies we
   hold, no removals are written and the source is marked `needs_look`.
6. **Publish policy:** a later valid-until date and an added scope publish at once (`reviewed_by = 'auto'`).
   Removals, new bodies, renames, removed scopes and earlier or cleared dates wait for a moderator in `/admin`
   (Certifiers tab). Scope events add or remove only their own codes, so an auto-published addition never sneaks a
   pending removal through. A renamed body gets a new slug; the old one 308s.
7. Address, city, country and registration number are refreshed from the official row without a change event.

It runs from the Worker's `scheduled()` handler (no cron is configured yet, see
[deployment.md](../deployment.md#cron-certifier-check)) and from `POST /api/certifiers/check` (moderators).

## Pages

`/certifiers` (hub, name/alias search, certifier × importing country table), `/certifiers/country/indonesia` (+
`.csv`), `/certifiers/[slug]`, `/certifiers/from/[country]`, `/certifiers/changes` (+ `.xml` Atom),
`/certifiers/alerts`, `/certifiers/methodology`, `/certifiers/guides/indonesia-halal-import-rules-2026`. Every page
carries "Always confirm with the authority before shipping". Sitemap `lastmod` is the last real data change, never
the last check.

## Not built yet

Other authorities (JAKIM, MOIAT, GAC), `/certifiers/expiring`, scope sub-pages, alert emails (double opt-in, digest),
sponsors and leads, logos and claimed profiles, the daily summary email, and the production cron trigger.
